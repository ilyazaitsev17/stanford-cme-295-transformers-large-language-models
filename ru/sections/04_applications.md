# 4. Применения

## 4.1. LLM в роли судьи

**❒ Определение.** LLM в роли судьи (LLM-as-a-Judge, LaaJ) — метод, при котором LLM оценивает заданные выходы по некоторому набору предоставленных критериев. Важно, что модель также способна сгенерировать обоснование своей оценки, что помогает с интерпретируемостью.

В отличие от метрик эпохи до появления LLM — таких как ROUGE (Recall-Oriented Understudy for Gisting Evaluation) — LaaJ не требует эталонного текста, что делает его удобным для оценки задач любого рода. В частности, LaaJ показывает сильную корреляцию с человеческими оценками, когда опирается на большую мощную модель (например, GPT-4), поскольку для хорошей работы методу нужны способности к рассуждению.

**Примечание:** LaaJ полезен для быстрых итераций оценки, но важно отслеживать согласованность между выходами LaaJ и оценками людей, чтобы убедиться в отсутствии расхождений.

**❒ Типичные смещения.** Модели LaaJ могут демонстрировать следующие смещения (biases):

| Смещение | Проблема | Решение |
|---|---|---|
| **Позиционное смещение** | Отдаёт предпочтение первой позиции в попарных сравнениях | Усреднять метрику по случайно переставленным позициям |
| **Смещение к многословности** | Отдаёт предпочтение более развёрнутому содержанию | Добавить штраф за длину выхода |
| **Смещение само-предпочтения** | Отдаёт предпочтение выходам, сгенерированным самой моделью | Использовать судью на основе другой базовой модели |

Способом устранить эти проблемы может быть дообучение собственного LaaJ, но это требует значительных усилий.

**Примечание:** приведённый список смещений не является исчерпывающим.

## 4.2. RAG

**❒ Определение.** Генерация с дополнением через поиск (Retrieval-Augmented Generation, RAG) — метод, который даёт LLM доступ к релевантным внешним знаниям для ответа на заданный вопрос. Это особенно полезно, когда нужно учесть информацию, появившуюся после даты отсечения знаний, на которых обучалась LLM.

При наличии базы знаний $D$ и вопроса модуль поиска (Retriever) извлекает наиболее релевантные документы, затем дополняет (Augment) промпт релевантной информацией и только после этого генерирует (Generate) ответ.

**Примечание:** этап поиска обычно опирается на эмбеддинги, получаемые из моделей типа «только энкодер».

**❒ Гиперпараметры.** База знаний $D$ инициализируется так: документы нарезаются на фрагменты (chunks) размера $n_c$, после чего каждый фрагмент кодируется в вектор размерности $\mathbb{R}^d$.

## 4.3. Агенты

**❒ Определение.** Агент — это система, которая автономно преследует цели и выполняет задачи от имени пользователя. Для этого она может использовать различные цепочки вызовов LLM.

**❒ ReAct.** Reason + Act (ReAct) — фреймворк, который позволяет выстраивать несколько цепочек вызовов LLM для решения сложных задач. Он состоит из следующих шагов:

- **Наблюдение (Observe):** синтезировать предыдущие действия и явно сформулировать, что известно на текущий момент.
- **Планирование (Plan):** детально определить, какие задачи нужно решить и какие инструменты вызвать.
- **Действие (Act):** выполнить действие через API или найти релевантную информацию в базе знаний.

**Примечание:** оценивать агентную систему сложно. Тем не менее это можно делать как на уровне отдельных компонентов — через локальные пары «вход-выход», — так и на уровне всей системы — через цепочки вызовов.

## 4.4. Reasoning-модели

**❒ Определение.** Reasoning-модель — модель, которая опирается на следы рассуждений в стиле CoT, чтобы решать более сложные задачи в математике, программировании и логике. Примеры reasoning-моделей: серия o от OpenAI, DeepSeek-R1 и Gemini Flash Thinking от Google.

**Примечание:** DeepSeek-R1 явно выводит свой след рассуждений между тегами `<think>`.

**❒ Масштабирование.** Для усиления способностей к рассуждению используются два типа методов масштабирования:

| Тип | Описание | Иллюстрация |
|---|---|---|
| **Масштабирование на этапе обучения** (train-time scaling) | Дольше выполнять RL, чтобы модель научилась выстраивать следы рассуждений в стиле CoT перед выдачей ответа | Качество растёт с числом шагов RL |
| **Масштабирование на этапе вывода** (test-time scaling) | Дать модели «подумать» дольше перед выдачей ответа, принудительно удлиняя рассуждение ключевыми словами вроде «Wait» (бюджетное принуждение) | Качество растёт с длиной CoT |
